## 摘要
我们引入了Frontier解码器，一种用于稀疏量子解码问题的剪枝动态规划解码器。Frontier按选定顺序处理错误变量，合并具有相同残留综合征和逻辑标签的前缀，并通过仅保留一个狭窄的评分前沿来近似逻辑陪集后验质量。在没有剪枝的情况下，该递归是精确的有序推理，但具有指数复杂度。在代码容量设置下，该解码器达到了接近表面码和颜色码的最优阈值。在电路级噪声模型中，它以非常小的平均保留列表大小实现了最先进的性能：在物理错误率为0.001时，对于粗码$[[144,12,12]]$，平均保留列表大小小于100。当列表大小恒定时，解码器具有线性复杂度，这表明了低延迟实现的可行性。

## Abstract
We introduce the Frontier decoder, a pruned dynamic-programming decoder for sparse quantum decoding problems. Frontier processes error variables in a chosen order, merges prefixes with the same residual syndrome and logical label, and approximates logical-coset posterior masses by retaining only a narrow scored frontier. Without pruning, the recursion is exact ordered inference with exponential complexity.   In the code-capacity setting, the decoder reaches thresholds close to optimal for the surface code and the color code. In the circuit-level noise model, it achieves state-of-the-art performance with a very small average retained list size: less than 100 for the gross code $[[144,12,12]]$ at a physical error rate of $0.001$. When the list size is constant, the decoder has linear complexity, suggesting the possibility of low-latency implementations.

### 2. 论文提出的方法论

#### 核心思想
- **有序动态规划 + 剪枝**：将错误变量按固定顺序（列序）逐一处理，记录每个前缀的**残留综合征**（active boundary上的综合征缺失）和**逻辑标签**，合并具有相同边界状态的前缀（利用量子简并性压缩）。
- **保留窄前沿**：通过**分数差距剪枝**（score-gap pruning）和硬上界K，仅保留得分最高的少量状态，近似后验质量分布。无剪枝时递归是精确但指数复杂的变量消除法。

#### 关键技术细节
1. **边界状态定义**：对于已处理的前缀，维护活跃校验集Γt，记录残留综合征qt和累计逻辑标签λt，记为σt=(qt,λt)。相同状态的前缀合并（质量相加）。
2. **状态转移**：对每个幸存状态，分支到下一变量的所有可能取值，更新综合征、逻辑标签和日志质量；完成校验后验证一致性并丢弃错误分支；合并重复状态。
3. **剪枝准则**：每个状态分配**剪枝分数 S = P + αC**，其中P是前缀对数质量，C是**后缀相容性分数**（基于行独立近似的对数概率估计），α=0.8。保留分数在最佳分数±Δ内的状态，最多K个。
4. **列排序**：采用**截止顺序**（deadline ordering）——优先放置能尽早闭合校验行的变量，使活跃边界规模小，便于剪枝。委员会解码同时使用正向和反向截止顺序。
5. **终端决策**：所有变量处理完后，按逻辑标签聚合保留状态的指数质量，输出质量最大的逻辑类。

### 7. 优点

1. **几何无关性**：仅依赖有序校验矩阵，适用于非局域量子LDPC码（如BB码）。
2. **利用量子简并性**：合并相同边界状态的前缀，将多个物理错误压缩为一个条目，减轻列表竞争。
3. **自适应剪枝**：通过Δ实现按需调整前沿大小，避免固定大小带来的性能损失。
4. **委员会解码**：使用正向和反向截止顺序提升鲁棒性。
5. **诊断能力**：能区分支持丢失和排名错误，提供调优方向。

### 8. 不足与局限

1. **排序依赖**：性能对变量顺序敏感，当前截止顺序可能不是最优，尤其对大代码仍需改进。
2. **后缀评分粗糙**：忽略行间相关性，仅用行独立乘积相加，可能误导剪枝。α=0.8是经验值，缺乏理论保证。

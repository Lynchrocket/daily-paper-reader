## 摘要
量子纠错(QEC)对于构建可扩展的容错量子计算机不可或缺。有效的QEC要求严格的实时解码：解码器必须在时间尺度内(通常为微秒量级)处理综合征测量并确定校正，以避免数据积压。扩展到大量逻辑量子比特进一步需要大量的计算资源。在这项工作中，我们提出了一种名为\emph{THQLink}的架构，用于利用高性能计算(HPC)资源实时解码量子纠错码。连接HPC与量子处理单元(QPU)控制系统的网络基于TH-Express构建，可适配不同的量子技术及其相关的控制栈。我们报告了平均2.944 $μ$s的往返延迟，每增加一跳的增量开销为130 ns。使用并行窗口策略，我们展示了在CPU上使用基于匹配的解码器对距离高达19的表面码进行实时解码(每个QEC轮次1 $μ$s)。我们的工作为容错量子计算中的实时解码提供了一个可扩展的框架。它可以很容易地应用于以QPU和HPC资源紧密集成为特征的量子中心超级计算机，从而有效支持混合量子经典算法和从QPU卸载的计算密集型工作负载。

## Abstract
Quantum error correction (QEC) is indispensable for building scalable fault-tolerant quantum computers. Effective QEC demands stringent real-time decoding: the decoder must process syndrome measurements and determine corrections within a time scale--typically on the order of microseconds, to avoid data backlog. Scaling to large number of logical qubits further necessitates significant computational resources. In this work, we propose an architecture, called \emph{THQLink}, for real-time decoding of quantum error correction codes using high-performance computing (HPC) resources. The network connecting the HPC and the control system of quantum processing unit (QPU) is built on TH-Express and can be adapted to different quantum technologies and their associated control stacks. We report a round-trip latency of 2.944 $μ$s on average, with an incremental overhead of 130 ns per additional hop. Using a parallel window strategy, we demonstrate real-time decoding (1 $μ$s per QEC round) of the surface code up to distance 19 using a matching-based decoder on CPUs. Our work presents a scalable framework for real-time decoding in fault-tolerant quantum computing. It can be readily applied to quantum-centric supercomputers that feature tight integration between QPU and HPC resources, thereby enabling efficient support for hybrid quantum-classical algorithms and computation-intensive workloads offloaded from the QPU.

- **核心问题**：量子纠错（QEC）是构建可扩展容错量子计算机的关键技术，而实时解码是其中最具挑战性的环节之一。解码器必须在极短的时间（对于超导量子比特通常约 1 μs）内完成综合征（syndrome）处理并返回校正指令，否则会导致数据积压，破坏容错能力。
- **现有方案的矛盾**：
  - 基于 CPU/GPU 的软件解码器（如 Sparse Blossom、Fusion Blossom、BP+OSD 等）灵活、可编程，但通过传统 TCP/IP 网络连接量子控制系统时延迟高且不确定，难以满足实时要求。
  - 基于 FPGA/ASIC 的专用硬件解码器速度快、延迟低，但一旦 QEC 码型、噪声模型或算法改变，就需要重新设计芯片，缺乏灵活性。
  - 现有 NVQLink 架构虽然尝试通过低延迟网络耦合 QPU 与 HPC，但保留了以太网协议开销，且尚无完整的实时解码闭环验证。
- **本文目标**：提出一种名为 **THQLink** 的架构，利用通用高性能计算（HPC）集群作为解码引擎，通过自研的高性能互连网络 **TH-Express** 与量子控制系统（QSC）紧密耦合，在保证实时性的同时兼顾可编程性、可扩展性和对不同量子平台的适配性。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

- **核心思想**：将 QPU 的综合征数据通过低延迟、确定性强的专用网络 TH-Express 实时传输到 HPC 节点，由通用 CPU 执行解码算法，并将校正结果同样通过网络返回 QPU，形成闭环。整个架构强调“通用计算资源 + 高速互连”而非专用解码硬件。
- **THQLink 架构组成**：
  - **QSC 侧**：FPGA 实现 TH-Express 的物理层/链路层，以及自定义的“综合征到包生成器”（Syndrome-to-Packet generator）和校正逻辑。
  - **网络层**：TH-Express 交换机构成无损、低延迟的交换网络，可扩展至多 HPC 机架。
  - **HPC 侧**：普通 CPU/GPU 节点作为解码器运行平台，通过 TH-Express NIC 接入网络，负责解码、任务调度、预处理等。
- **关键设计**：
  - **Mini-Packet（MP）**：轻量级短消息机制，用于承载实时综合征数据，降低协议开销。
  - **RDMA**：用于批量数据搬运。
  - **并行窗口解码策略**（附录 A）：将时空解码图划分为两类窗口：
    - **A 窗口**：包含核心（core）区域和两侧缓冲区（buffer），缓冲区提供上下文信息，但只保留核心区域的校正结果。
    - **B 窗口**：位于相邻 A 窗口之间的“接缝”窗口，接收 A 窗口产生的人工缺陷（artificial defect），解决跨窗口的全局拓扑信息。
  - 窗口参数：步长 $s=(d+1)/2$，缓冲区大小 $b=(d+1)/2$，A 窗口宽度 $w = s + 2b = 3(d+1)/2$。A 窗口并行解码完成后，B 窗口随即并行解码，整体延迟约为 A+B 两个阶段最大延迟之和，与窗口总数基本无关。
- **解码算法**：使用最小权完美匹配（MWPM）解码器，具体实现为 Sparse Blossom，作为基础解码器。
- **端到端延迟定义**：$\tau_{e2e} = t_{corr} - t_{syn,last}$，其中 $t_{syn,last}$ 为最后一个综合征轮次开始传输的时间，$t_{corr}$ 为 FPGA 完整收到校正集合的时间。该指标包含传输、解码、校正映射和返回的全部延迟。

## 6. 论文的主要结论与发现

- **网络性能**：

- **实时解码能力**：
  - 全局 MWPM 在 $p=0.1\%$、$d \times d \times d$ 场景下可实现距离 13 的实时解码（每轮 < 1 μs）。
  - 并行窗口解码显著提升可支持的码距：在 $d \times d \times 5d$、$p=0.1\%$ 时可支持距离 15；在 $d \times d \times 10d$ 时可支持距离 19，且每轮延迟约 1 μs。
  - 在较高错误率 $p=0.3\%$ 时，绝对延迟增加（因为 syndrome 图更密集），但并行窗口依然优于全局解码。
- **准确性**：
  - 并行窗口相比全局 MWPM 逻辑错误率略有升高（约一个数量级以内），原因是窗口边界上的缺陷处理是局部近似，但通过 B 窗口恢复了大部分全局信息。
- **总体结论**：THQLink 展示了通用 HPC 资源配合低延迟网络可以实现实时 QEC 解码，且具有可编程性和可扩展性，是硬件固定方案之外的有力替代。

## 7. 优点

- **架构创新性**：首次针对 QEC 实时解码提出“QPU + 通用 HPC + 自研低延迟网络”的闭环架构，突破了传统方案在延迟与灵活性之间的取舍。
- **低延迟互连**：TH-Express 相比 NVQLink/RoCE 协议开销更低，往返延迟降低 23.3%，且每跳增量极低，支持多级扩展。
- **并行窗口策略**：将解码从串行窗口依赖中解放出来，实现窗口间并行，解码吞吐可随核心数扩展，是解决长序列解码瓶颈的关键。
- **完整的闭环验证**：不仅做了网络 loopback 测试，还实测了从 FPGA 发送 syndrome 到解码并返回校正的完整流程，更贴近实际部署。
- **可适配性**：TH-Express 可适配多种量子技术（超导、中性原子、离子、光子），不像专用 ASIC/FPGA 固定于特定编码方案。
- **可扩展性**：交换网络支持通过增加端口/机架扩展计算资源，且延迟增加微乎其微。

## 8. 不足与局限

- **与超导量子比特的控制系统集成真实性有限**：实验中使用 FPGA 模拟 QSC，未在真实量子控制系统上验证，实际控制面可能会引入额外延迟。
- **未与其他解码方法进行直接的端到端比较**：仅对比了全局 MWPM 与并行窗口 MWPM，未与 FPGA/ASIC 实现（如 collision clustering、BP+OSD 硬件等）在同一套硬件和噪声模型下对比。
- **资源信息不透明**：未说明并行窗口中实际使用了多少个 CPU 核心、如何分配窗口到核心，以及多节点扩展时的负载均衡细节；也未报告能耗。
- **逻辑错误率统计可能不够精确**：对于距离较大的情况，样本量可能不足以获得可靠的低错误率估计，尤其当 $P_{fail}$ 低于 $10^{-6}$ 时，误差可能较大。
- **仅验证了表面码**：虽然提及 qLDPC 码是未来工作，但当前结论仅针对表面码。qLDPC 码的图结构可能更复杂，对网络和内存的需求不同。
- **每跳延迟的扩展性分析较粗**：仅通过简单回环测试推测多跳延迟，实际多级网络拥塞、路由冲突可能导致延迟恶化。
- **未讨论故障转移与可靠性机制**：在实时系统中，网络丢包或节点故障的处理对实际部署至关重要，论文未涉及。
- **硬件平台较旧**：使用的 Xeon Gold 6348（Ice Lake）和 FPGA 并非最新，实际生产级系统可能具有不同性能特征。

## 总结

THQLink 提出了一种将通用 HPC 与量子控制系统通过低延迟专用网络紧密耦合的实时 QEC 解码架构，并利用并行窗口策略将 MWPM 解码的实时能力扩展到表面码距离 19，兼顾了性能、灵活性和可扩展性。实验设计较为全面，但存在仿真环境、对比范围、资源透明度等方面的局限。该工作为量子中心超算的实时解码提供了有价值的工程框架和实证数据。
